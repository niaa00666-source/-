# Задачи — автономное приложение

Раздел задач, вынесенный из дизайн-системы `scrambled-ui` в самостоятельный
проект: его можно запустить и задеплоить без доступа к приватному реестру
`npm-registry.webinar.ru`.

## Запуск

```bash
npm install
npm run dev
```

Откроется на <http://127.0.0.1:5174>.

```bash
npm run build      # tsc + vite build → dist/
npm run preview    # посмотреть собранное
npm run typecheck
```

## Деплой на Netlify

Настройки уже лежат в [`netlify.toml`](netlify.toml): команда `npm run build`,
каталог `dist`, Node 22 и SPA-редирект на `index.html`. При подключении
репозитория Netlify подхватит их сам — руками ничего вводить не нужно.

## Что внутри

```
src/
├── App.tsx     адаптер: состояние, фильтрация, сортировка, localStorage
├── kit/        исходники @scrambled/ui-kit (перенесены как есть)
└── tasks/      экран задач из @scrambled/screens (перенесён как есть)
```

**Экран и кит перенесены без правок** — ровно те же файлы, что в монорепозитории.
Единственное исключение: в `src/kit/index.ts` поправлен путь к собственным
стилям кита (в монорепозитории они лежат уровнем выше). Импорты вида
`@scrambled/ui-kit` продолжают работать благодаря алиасам в
[`vite.config.ts`](vite.config.ts) и `tsconfig.json`, поэтому обновить экран или
кит можно простым копированием файлов поверх.

Приватный реестр не нужен: кит зависит только от публичных пакетов npm.

### Границы слоёв

Экран (`src/tasks`) чист по контракту — в нём нет ни сети, ни `window`, ни
хранилища. Всё это живёт в адаптере `src/App.tsx`: он же владеет состоянием,
считает фильтры, сортировку, счётчики разделов и просроченность, и он же пишет
задачи в `localStorage` под ключом `tasks-app.tasks.v1`. Данные мокованы, бэкенда
нет.

## Отличия от витрины дизайн-системы

- убран глобальный рейл продуктов (`showProductRail={false}`) — приложение про
  одни задачи;
- убран переключатель сценариев прототипа;
- задачи сохраняются в `localStorage` и переживают перезагрузку, а не живут
  только в памяти вкладки.

## Известное ограничение

Оболочка держит минимальную ширину **1120 px** (сайдбар 280 + рабочая область
784 + внутренние отступы) и ниже неё не перестраивается, а обрезается вьюпортом
без горизонтальной прокрутки. В узком окне правая часть экрана — включая
плавающую кнопку «+» — оказывается за краем; создать задачу в этом случае можно
кнопкой «Создать задачу» в сайдбаре. Адаптив под узкие экраны в исходной
дизайн-системе отложен сознательно.
