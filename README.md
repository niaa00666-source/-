# Задачи — автономное приложение

Раздел задач, вынесенный из дизайн-системы `scrambled-ui` в самостоятельный
проект: его можно запустить и задеплоить без доступа к приватному реестру
`npm-registry.webinar.ru`.

## Запуск

```bash
npm install
npm run dev
```

Откроется на <http://127.0.0.1:5174>.

```bash
npm run build      # tsc + vite build → dist/
npm run preview    # посмотреть собранное
npm run typecheck
```

## Деплой на Netlify

Настройки уже лежат в [`netlify.toml`](netlify.toml): команда `npm run build`,
каталог `dist`, Node 22 и SPA-редирект на `index.html`. При подключении
репозитория Netlify подхватит их сам — руками ничего вводить не нужно.

## Что внутри

```
src/
├── App.tsx     адаптер: состояние, фильтрация, сортировка, localStorage
├── kit/        исходники @scrambled/ui-kit (перенесены как есть)
└── tasks/      экран задач из @scrambled/screens (перенесён как есть)
```

**Экран и кит перенесены без правок** — ровно те же файлы, что в монорепозитории.
Единственное исключение: в `src/kit/index.ts` поправлен путь к собственным
стилям кита (в монорепозитории они лежат уровнем выше). Импорты вида
`@scrambled/ui-kit` продолжают работать благодаря алиасам в
[`vite.config.ts`](vite.config.ts) и `tsconfig.json`, поэтому обновить экран или
кит можно простым копированием файлов поверх.

Приватный реестр не нужен: кит зависит только от публичных пакетов npm.

### Границы слоёв

Экран (`src/tasks`) чист по контракту — в нём нет ни сети, ни `window`, ни
хранилища. Всё это живёт в адаптере `src/App.tsx`: он же владеет состоянием,
считает фильтры, сортировку, счётчики разделов и просроченность, и он же пишет
задачи в `localStorage` под ключом `tasks-app.tasks.v1`. Данные мокованы, бэкенда
нет.

## Отличия от витрины дизайн-системы

- убран глобальный рейл продуктов (`showProductRail={false}`) — приложение про
  одни задачи;
- убран переключатель сценариев прототипа;
- задачи сохраняются в `localStorage` и переживают перезагрузку, а не живут
  только в памяти вкладки.

## Адаптив

Оболочка `AppShell` из кита держит минимальную ширину **1120 px** и ниже неё не
перестраивается, а обрезается вьюпортом без горизонтальной прокрутки — в узком
окне правая часть экрана вместе с кнопкой создания уезжает за край. В исходной
дизайн-системе перестроение под узкие экраны отложено сознательно.

Поэтому ниже 1120 px приложение рисует **свою** раскладку и оболочку не
использует ([`src/use-compact-layout.ts`](src/use-compact-layout.ts) плюс ветка
в `App.tsx`):

- шапка с кнопкой вызова разделов и названием продукта;
- разделы уезжают в выдвижную панель (`Sheet`) и закрываются по выбору;
- список занимает всю ширину и прокручивается в собственном контейнере — экран
  рассчитывает на него: об него меряются `min-h-full` секции и липкая кнопка
  создания.

Фильтры переносятся по строкам, карточки сжимаются, диалог редактора помещается
на 375 px.

### Колонка контента

Контент собран в одну колонку `max-w-4xl`, центрированную в рабочей области:
заголовок, фильтры, список и кнопка создания стоят в общей сетке. До этого
список был прижат влево, а фильтры центрировались по всей ширине — на широком
мониторе они разъезжались, и справа оставалось пустое поле.

Проверено на 375, 768, 1280, 1440 и 1900 px: горизонтальной прокрутки нет ни на
одной ширине, кнопка создания попадает под курсор везде. На 1440 колонка 896 px
с равными полями по 132; на 375 занимает всю ширину.

**Это единственная правка в самом экране задач** — остальные его файлы и весь
кит перенесены без изменений. В монорепозитории `packages/screens/src/tasks/`
такой правки пока нет, так что при обновлении копированием её нужно либо
перенести туда, либо наложить заново.
